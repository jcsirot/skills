# HTML Review Guide

Apply this guide to HTML documents, server-rendered templates, component
templates, and markup generated by another language. Review the template
engine's escaping and the browser behavior of the rendered output.

## Code quality, accessibility, and performance

- Prefer semantic elements and a coherent heading, landmark, list, table, and
  form structure. Do not use ARIA to compensate for incorrect native markup.
- Check labels, keyboard access, focus order, visible focus, error messaging,
  names/roles/values, contrast, language metadata, and reduced-motion or
  alternative content requirements.
- Check form methods, autocomplete, input types, constraints, validation
  messages, disabled/loading states, and preservation of user input after
  errors.
- Check responsive behavior, viewport metadata, image dimensions and
  alternative text, lazy loading, and avoidable render-blocking resources.
- Check duplicate IDs, invalid nesting, incorrect table semantics, broken
  links, missing document metadata, and behavior when JavaScript is absent or
  delayed.

## Security

- Verify that server-side templates escape text, attribute, URL, CSS, and
  JavaScript contexts independently. Do not treat HTML escaping as sufficient
  for every context.
- Check user-controlled URLs, `href`, `src`, `action`, `iframe`, `object`,
  `embed`, and `form` targets for dangerous schemes, open redirects, SSRF
  through server-side fetches, and untrusted embedding.
- Check inline scripts, event-handler attributes, inline styles, and dynamic
  markup against the application's CSP and trusted-types policy.
- Check forms and state-changing links for CSRF protections, origin behavior,
  autocomplete handling, and accidental exposure of secrets or personal data.
- Check external resources, `target="_blank"`, iframe sandboxing, referrer
  policy, and security headers where the template controls them.
